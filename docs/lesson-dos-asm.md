# DOS とアセンブリ入門の課題

本物の MS-DOS 4.00 を DOSBox-X で起動し、NASM で作った小さなプログラムを動かすまでの課題です。
知識ゼロから始める前提で、つまずいた点とその理由もまとめています。

> このファイルは UTF-8 の日本語なので、DOS の中では読めません。ホスト側（Linux）で開いてください。

---

## 0. まず知っておくこと

**DOS（Disk Operating System）** は 1980〜90 年代のパソコンの OS です。マウスは使わず、文字でコマンドを打って操作します。
DOSBox-X は、DOS が動く古いパソコンを今の PC の中で真似するソフトです。
この環境では、その中で Microsoft が公開した **MS-DOS 4.00**（1988 年）のソースからビルドしたものを起動します。

| 言葉 | 意味 | この環境での例 |
|---|---|---|
| ドライブ | ファイルの置き場所の一番上。アルファベット 1 文字で表す | `A:`、`B:` |
| ディレクトリ | フォルダーのこと。区切りは `/` ではなく `\` | `A:\` |
| プロンプト | コマンドを待っている合図。今いる場所が表示される | `B:\>` |
| ファイル名 | 「名前 8 文字 + `.` + 拡張子 3 文字」まで（8.3 形式）。大文字と小文字は区別しない | `HELLO.ASM` |
| `.COM` | DOS がそのまま実行できるプログラムの形式 | `HI.COM` |

### 起動のしかた

ホストのターミナルで次のコマンドを実行します。

```bash
cd /home/ponzu/Documents/dosbox && make run
```

このコマンドは、次のことを自動で行います。

1. ホストの `nasm` で `hello.asm` を組み立て、`work/HELLO.COM` に置く
2. `work/` の中身をフロッピー（`B:`）に入れる
3. DOSBox-X で MS-DOS 4.00 を起動する。`JPKEY: JP106 keyboard layout installed` と出て、`A:\>` で止まる
4. DOSBox-X を閉じると、`B:` の中身を `work/` に書き戻す

**終わり方**：DOSBox-X のウィンドウを閉じます（× ボタン）。MS-DOS には「終了」のコマンドがありません（`exit` を打っても何も起きません）。
ウィンドウを閉じたあとにターミナルへ `B:` の中身が表示されれば、書き戻しは終わっています。

`hello.asm` を組み立て直す必要がないときは、`make msdos4-run` でも同じように起動できます。

### ドライブの使い分け

| ドライブ | 中身 | 使い方 |
|---|---|---|
| `A:` | MS-DOS の起動フロッピー（ホストの `build/msdos4.img`） | MS-DOS 本体とコマンド（`EDLIN`、`DEBUG` など）が入っている。**ここには書かない**。作り直されると消える |
| `B:` | ホストの `work/` の中身 | **作業はすべてここで行う**。起動のたびに `work/` から作り直され、終了すると `work/` に戻る |
| `C:` | 起動した時点のプロジェクトフォルダーの写し（DOSBox-X が FAT のディスクに変換して見せている） | `C:\NASM` の NASM や `C:\LESSON` の材料を**読む**ためだけに使う。**ここに書いたものは、閉じると消える**（ホストに戻らない） |

- `B:` はフォルダーの中を入れ替えません。`B:` の一番上（`B:\`）だけを使ってください（`B:\LESSON` のように中に作ったフォルダーは書き戻されません）。
- ホスト側で `work/` に置くファイルも、8.3 形式の英数字の名前にします（例：`hi.asm`）。長い名前のファイルは `B:` に入りません。
- ホストで作ったものを DOS に渡すとき、DOS で作ったものをホストで使うときは、**いったん DOSBox-X を閉じる**必要があります。開いている間は、両者はつながっていません。

### ホストと DOS の役割

組み立て（アセンブル）は、MS-DOS の中でもホストでもできます。

**MS-DOS の中で組み立てる（いつもの方法）**：起動したら、最初に PATH を設定します（起動のたびに 1 回。起動直後の PATH は空です）。

```
path a:\;c:\nasm
b:
edlin hi.asm
nasm -f bin -o hi.com hi.asm
hi
```

`C:\NASM` の NASM は現代の NASM 3.02（32 ビット、`CWSDPMI.EXE` を自動で読み込む）です。1988 年の MS-DOS 4.00 の時代には NASM はまだありませんでした。CPU を遅くしているので、1 回の組み立てに時間がかかります。

**ホストで組み立てる**：DOSBox-X を閉じてから、ホストのターミナルで組み立てます。

```
ホスト（Linux）   work/hi.asm を書く・nasm で work/hi.com を作る
     ↓ 起動（work/ → B:）
MS-DOS 4.00      B: で hi を実行する・EDLIN で hi.asm を直す
     ↓ 終了（B: → work/）
ホスト（Linux）   直された work/hi.asm を、また nasm で組み立てる
```

### キーボード

日本語キーボードの刻印どおりに打てます。MS-DOS 4.00 には日本語配列がないので、自作の常駐プログラム `JPKEY.COM`（ソースは `jpkey.asm`）を起動時に読み込んでいます。

### 注意

- DOS では日本語を使えません。ファイル名もファイルの中身も、英数字だけにします。
- 打ち間違えると `Bad command or file name` と表示されます。慌てずにつづりを確認してください。

## 課題 1：中を見て歩く

使うコマンド：`ver`（バージョンを表示）、`dir`（一覧を表示）、`b:` / `a:`（ドライブを移る）、`cls`（画面を消す）

1. `ver` を打ち、MS-DOS のバージョンが表示されることを確認する
2. `dir` を打ち、`A:` の中身を見る。`IO.SYS` と `MSDOS.SYS`（MS-DOS 本体）、`COMMAND.COM`（コマンドを受け付けるプログラム）、`EDLIN.COM`（エディター）などがある
3. `b:` を打って `B:` に移り、`dir` で `HELLO.COM` があることを確認する
4. `hello` と打って実行する
5. `a:` で `A:` に戻り、`cls` で画面を消す

**確認**：プロンプトが `A:\>` → `B:\>` → `A:\>` と変わること。`hello` で `Hello, slow world!` と表示されること。

## 課題 2：EDLIN でファイルを作る

使うコマンド：`edlin ファイル名`、`type ファイル名`（中身を表示）

EDLIN は、1 行ずつ番号で編集するエディターです。画面の好きな場所にカーソルを動かして書くことはできません。

| EDLIN のコマンド | 意味 |
|---|---|
| `i` | 入力を始める（insert）。Ctrl+C で入力を終える |
| `l` | 一覧を表示する（list） |
| 数字（例：`1`） | その行を書き直す |
| `e` | 保存して終わる（end） |
| `q` | 保存せずに終わる（quit）。`Abort edit (Y/N)?` に `y` |

1. `b:` で `B:` に移る（プロンプトが `B:\>` になっていることを確認する）
2. `edlin memo.txt` を打つ。`New file` と `*` が表示される
3. `i` と Enter を押すと `1:*` が出るので、英語で 1 行書いて Enter（例：`my first dos file`）
4. `2:*` が出たら Ctrl+C を押して入力を終える
5. `l` で書いた行を確認し、`e` で保存して終わる
6. `type memo.txt` で、書いた内容が表示されることを確かめる

**確認**：DOSBox-X を閉じたあと、ホスト側で `/home/ponzu/Documents/dosbox/work/MEMO.TXT` を開くと、同じ内容が見えること。

**つまずきやすい点**：`b:` を忘れると、ファイルが `A:` にできます。`A:` はホストに戻らないうえ、起動フロッピーを作り直すと消えます。

## 課題 3：プログラムを組み立てて動かす

ここではホストのターミナルから始めます。

**手順 1：材料を work/ にコピーする（ホスト）**

```bash
cd /home/ponzu/Documents/dosbox
cp hello.asm work/hi.asm
```

**手順 2：NASM で組み立てる（ホスト）**

```bash
nasm -f bin -o work/hi.com work/hi.asm
```

| 部分 | 意味 |
|---|---|
| `nasm` | アセンブラ（組み立てるプログラム）を呼ぶ |
| `-f bin` | 出力の形式。そのままの機械語にする（`.COM` 用） |
| `-o work/hi.com` | 出来上がりのファイル名（output）。**必ず `.com`**。`.asm` を書くとソースが上書きされて消える |
| `work/hi.asm` | 材料のソースファイル |

何も表示されずにプロンプトに戻れば成功です。

**手順 3：MS-DOS を起動する（ホスト）**

```bash
make msdos4-run
```

**手順 4：実行する（MS-DOS）**

```
b:
dir
hi
```

**確認**：`dir` に `HI ASM` と `HI COM` が並び、`hi` で `Hello, slow world!` と表示されること。

### なぜ組み立てが必要か

| ファイル | 中身 | 実行できる？ |
|---|---|---|
| `HI.ASM` | 人間が読むための命令の文章（ソース） | できない（ただのテキスト） |
| `HI.COM` | CPU が実行できる機械語 | できる（`hi` と打つ） |

`hi` と打つと、DOS は `HI.COM`、`HI.EXE`、`HI.BAT` を探します。`HI.ASM` しかないと `Bad command or file name` になります。

### つまずきやすい点

| 症状 | 原因 | 直し方 |
|---|---|---|
| MS-DOS で `nasm` や `edlin` が `Bad command or file name` | PATH が空（起動直後はいつも空） | `path a:\;c:\nasm` を打つ。または `a:edlin`、`c:\nasm\nasm` のように場所を付けて呼ぶ |
| `nasm -f bin hi.com hi.asm` がうまくいかない | `-o` を忘れて、`hi.com` も材料だと思われた | `-o hi.com` と書く |
| `hi` が `Bad command or file name` | `A:` にいる、または `hi.com` を作る前に起動した | `b:` に移る。起動中ならウィンドウを閉じ、ホストで組み立ててから起動し直す |
| `unknown optimization option -OH` | オプションを大文字で打っている。NASM では `-O`（最適化）と `-o`（出力先）、`-F`（デバッグ形式）と `-f`（出力形式）は別物 | オプションは小文字で打つ。`Caps Lock` がオンになっていないか確認する |
| `B:` にファイルがない | ファイル名が 8.3 形式でない、または `work/` の中のフォルダーに置いた | `work/` の一番上に、短い英数字の名前で置く |

DOS のコマンド名とファイル名は大文字・小文字を区別しませんが、**NASM のオプションは区別します**。

## 課題 4：表示する文字を変える

**手順 1：EDLIN で書き換える（MS-DOS）**

1. `b:` に移り、`edlin hi.asm` で開く
2. `l` で一覧を表示し、次の行の番号を探す（行が多くて流れたら、`10l` のように番号を付けると、その行の近くから表示する）
   ```nasm
   msg:    db "Hello, slow world!", 13, 10, "$"
   ```
3. その番号（例：`16`）を打つと、今の行と、書き直す欄（`16:*`）が表示される
4. 書き直す欄に、行全体を打ち直す。`"` と `"` の間だけを好きな英文にして、`13, 10, "$"` は残す
5. `l` で確認し、`e` で保存して終わる

**行を打ち直すのが大変なとき**：書き直す欄で **F3** を押すと、元の行がまるごと出てきます。Backspace で後ろから消して、打ち直す部分だけを入力できます。
何も入力せずに Enter を押すと、その行は変わりません。

| キー | 書き直す欄での動き |
|---|---|
| F1 | 元の行から 1 文字だけ出す |
| F2 + 文字 | 元の行の、その文字の手前までを出す |
| F3 | 元の行の残りを全部出す |
| Esc | 打った内容を取り消す |

**手順 2：組み立て直す（ホスト）**

DOSBox-X を閉じてから、もう一度組み立てて起動します。

```bash
nasm -f bin -o work/hi.com work/hi.asm
make msdos4-run
```

MS-DOS で `b:` に移り、`hi` と打って実行します。

**ポイント**：ソースを書き換えたら、**必ず組み立て直す**こと。`HI.COM` は古いソースから作ったものなので、組み立て直すまで中身は変わりません。

**知っておくこと**：EDLIN で保存すると、元のファイルが `HI.BAK`（backup）として残ります。また、ファイルの最後に Ctrl+Z（昔の「ファイルの終わり」の印）が付きます。NASM はどちらがあっても問題なく組み立てられます。

### 実験：`"$"` を消すとどうなるか

`"$"` を消して組み立て、実行すると、自分の文のあとに関係のない文字がたくさん表示されます。

**理由**：文字の表示に使っている DOS の機能（`INT 21h` の `AH=09h`）の決まりは、次の 1 つだけです。

> `DX` が指す場所から 1 文字ずつ表示し、**`$` が出てきたら止まる**

`$` がないと、DOS はプログラムの終わりを越えて、その後ろのメモリーに残っているものまで表示し続けます（DOS は使い終わったメモリーを消さないため、前に使われたデータの残りが出てきます）。
メモリーのどこかで `$` にぶつかったところで、やっと止まります。

これは **ASCII 文字かどうか**とも、**`org 0x100`** とも関係ありません。

- ソースの `keep this file ASCII only` というコメントは、「DOS のエディターは UTF-8 を表示できないので、ソースには英数字だけを書くこと」という意味です。
- `org 0x100` は「このプログラムはメモリーの 100h 番地に置かれる」という宣言です。`.COM` は DOS によって必ず 100h 番地に読み込まれる（その前の 0〜FFh には PSP という管理情報がある）ので、NASM はこの値を使って `msg` の番地を計算します。「ここまで」という上限の意味はありません。

**学べること**：アセンブリでは、終わりの印や長さを自分で用意しないと、誰も守ってくれません。
C の文字列の `\0` を忘れたときに起きるバッファオーバーリード（buffer over-read）と同じ種類のバグです。

実験が終わったら、`"$"` を元に戻しておいてください。

## 課題 5（挑戦）：2 行表示する

2 種類の文を、2 行に分けて表示させてください。

**ヒント**：

- 表示を担当しているのは、次の 3 行です。この 3 行をもう 1 組増やします。
  ```nasm
  mov dx, msg
  mov ah, 0x09
  int 0x21
  ```
- 増やしたほうでは、`msg` ではなく、新しく作る `msg2` を指すようにします。
- 一番下に、`msg:` の行を真似して `msg2:` の行を作ります。
- `13, 10` は改行、`"$"` は文字列の終わりの印です。
- 増やす場所は、`mov ax, 0x4C00`（プログラムを終える命令）**より前**です。後ろに置くとどうなるか、考えてみてください。
- EDLIN で行を増やすには、`i` の前に番号を付けます。`13i` なら、13 行目（`hello.asm` では `mov ax, 0x4C00` の行）の**前**に入力を始めます（Ctrl+C で終える）。

## 課題 6（挑戦・任意）：`$` を使わずに表示する

### `$` は誰の決まりか

`$` は、アセンブリ言語の決まりではありません。**DOS の `AH=09h` という機能だけの決まり**です。
アセンブリ言語の `db "Hello"` は、ただバイトを並べるだけです。文字列の終わりをどう伝えるかは、呼び出す相手（OS や関数）の約束で決まります。

| 呼び出す相手 | 文字列の終わりの伝え方 |
|---|---|
| DOS の INT 21h **AH=09h** | `$` で終わる |
| C 言語の `puts`、`printf` など | `\0` で終わる |
| DOS の INT 21h **AH=40h** | 長さを `CX` で渡す |
| Linux の `write` システムコール | 長さを `rdx` で渡す |
| Windows の `WriteFile` / `WriteConsole` | 長さを引数で渡す |

### 課題

`B:` で `copy hi.asm price.asm` を打って複製し、`price.asm` を AH=40h を使う形に書き換えて、`"Price: $5"` が最後まで表示されることを確かめてください。AH=09h では、`$` のところで表示が止まってしまう文です。

```nasm
        mov ah, 0x40            ; INT 21h AH=40h: write to handle
        mov bx, 1               ; handle 1 = stdout (screen)
        mov cx, msglen          ; number of bytes
        mov dx, msg             ; DS:DX -> string
        int 0x21
        ...
msg:    db "Price: $5", 13, 10
msglen  equ $ - msg             ; length, computed by NASM
```

**紛らわしい点**：`msglen equ $ - msg` の `$` は、文字列の終わりの印ではありません。
NASM の記号で、「今この行の番地」という意味です。`$ - msg` は「今の番地 − 文字列の先頭の番地 = 文字列の長さ」になります。

- 引用符の中の `"$"` → ただの文字（AH=09h の終わりの印）
- 引用符の外の `$` → NASM が計算する番地

### 参考：Linux（x86-64）で同じことをすると

```nasm
        mov rax, 1              ; syscall 1 = write
        mov rdi, 1              ; fd 1 = stdout
        mov rsi, msg            ; address of the string
        mov rdx, msglen         ; length
        syscall
```

「どこに・何を・何バイト」を渡すという形は、DOS の AH=40h と同じです。違うのはレジスタの名前と、呼び出し方（`int 0x21` か `syscall` か）だけです。

長さを渡す方式のほうが安全です。終わりの印を忘れても、メモリーの先まで読み進めることがありません。また、文字列の中に `$` や `\0` そのものを含められます。
