# DOS とアセンブリ入門の課題

DOSBox-X の中で DOS を触り、NASM で小さなプログラムを作って動かすまでの課題です。
知識ゼロから始める前提で、つまずいた点とその理由もまとめています。

> このファイルは UTF-8 の日本語なので、DOS の EDIT では読めません。ホスト側（Linux）で開いてください。

---

## 0. まず知っておくこと

**DOS（Disk Operating System）** は 1980〜90 年代のパソコンの OS です。マウスは使わず、文字でコマンドを打って操作します。
DOSBox-X は、DOS が動く古いパソコンを今の PC の中で真似するソフトです。

| 言葉 | 意味 | この環境での例 |
|---|---|---|
| ドライブ | ファイルの置き場所の一番上。アルファベット 1 文字で表す | `C:` = `/home/ponzu/Documents/dosbox` |
| ディレクトリ | フォルダーのこと。区切りは `/` ではなく `\` | `C:\NASM` |
| プロンプト | コマンドを待っている合図。今いる場所が表示される | `C:\LESSON>` |
| ファイル名 | 「名前 8 文字 + `.` + 拡張子 3 文字」まで（8.3 形式）。大文字と小文字は区別しない | `HELLO.ASM` |
| `.COM` | DOS がそのまま実行できるプログラムの形式 | `HI.COM` |
| PATH | コマンドを探す場所の一覧 | `C:\NASM;C:\EDIT;Z:\;...` |

### 起動のしかた

ホストのターミナルで次のコマンドを実行します。

```bash
cd /home/ponzu/Documents/dosbox && make dos
```

このコマンドは、次のことを自動で行います。

- `/home/ponzu/Documents/dosbox` を `C:` として mount し、`C:\>` から始める
- PATH に `C:\NASM`（アセンブラ）と `C:\EDIT`（エディター）を追加する
- 日本語キーボードの配列にする（`slow486.conf` の `keyb jp 437`）

### ドライブの使い分け

| ドライブ | 中身 | 使い方 |
|---|---|---|
| `C:` | ホストのフォルダー | **作業はすべてここで行う**。ホストからも同じファイルが見え、git でも管理できる |
| `Z:` | DOSBox-X がメモリーの中に作る仮想ドライブ | `MOUNT`、`KEYB` などのコマンドが置いてあるだけ。終了すると中身は消える |

手で起動して `Z:\>` から始まった場合は、`mount` にホストのパスを付けて C: を作ります。

```
mount c /home/ponzu/Documents/dosbox
c:
```

`mount c` だけでは、C: の状態を表示するだけで何も作られません。

### 注意

- DOS では日本語を使えません。ファイル名もファイルの中身も、英数字だけにします。
- 打ち間違えると `Bad command or filename` と表示されます。慌てずにつづりを確認してください。

## 課題 1：中を見て歩く

使うコマンド：`dir`（一覧を表示）、`cd 名前`（入る）、`cd ..`（1 つ上に戻る）、`cls`（画面を消す）

1. `dir` を打ち、`HELLO.ASM` があることを確認する
2. `cd nasm` で NASM のディレクトリに入り、`dir` で中を見る
3. `cd ..` で戻る
4. `cls` で画面を消す

**確認**：プロンプトが `C:\NASM>` → `C:\>` と変わること。

---

## 課題 2：自分の作業場所を作る

使うコマンド：`md 名前`（ディレクトリを作る）、`edit ファイル名`、`type ファイル名`（中身を表示）

1. `md lesson` で作業用のディレクトリを作り、`cd lesson` で中に入る
2. `edit memo.txt` を打ち、英語で 1 行書く（例：`my first dos file`）
3. `Alt` → `F` → `Save` で保存し、`Alt` → `F` → `Exit` で閉じる
4. `type memo.txt` で、書いた内容が表示されることを確かめる

**確認**：ホスト側で `/home/ponzu/Documents/dosbox/LESSON/MEMO.TXT` を開くと、同じ内容が見えること。これが mount の意味です。

**つまずきやすい点**：`md lesson` と `cd lesson` を忘れると、ファイルが `C:\`（プロジェクトの一番上）にできて、元からあるファイルと混ざります。プロンプトが `C:\LESSON>` になっているかを確認してください。

## 課題 3：用意されたプログラムを組み立てて動かす

`C:\LESSON>` にいる状態から始めます。

**手順 1：材料をコピーする**

```
copy ..\hello.asm hi.asm
```

`..\` は「1 つ上のディレクトリ」という意味です。`dir` で `HI ASM` が表示されれば OK です。

**手順 2：NASM で組み立てる（アセンブル）**

```
nasm -f bin -o hi.com hi.asm
```

| 部分 | 意味 |
|---|---|
| `nasm` | アセンブラ（組み立てるプログラム）を呼ぶ |
| `-f bin` | 出力の形式。そのままの機械語にする（`.COM` 用） |
| `-o hi.com` | 出来上がりのファイル名（output）。**必ず `.com`**。`.asm` を書くとソースが上書きされて消える |
| `hi.asm` | 材料のソースファイル |

486 を再現してわざと遅くしているので、少し時間がかかります。何も表示されずにプロンプトに戻れば成功です。

**手順 3**：`dir` で `HI COM` が増えたことを確かめる

**手順 4**：`hi` と打って実行する

**確認**：`Hello, slow world!` と表示されること。

### なぜ組み立てが必要か

| ファイル | 中身 | 実行できる？ |
|---|---|---|
| `HI.ASM` | 人間が読むための命令の文章（ソース） | できない（ただのテキスト） |
| `HI.COM` | CPU が実行できる機械語 | できる（`hi` と打つ） |

`hi` と打つと、DOS は `HI.COM`、`HI.EXE`、`HI.BAT` を探します。`HI.ASM` しかないと `Bad command or filename` になります。

### つまずきやすい点

| 症状 | 原因 | 直し方 |
|---|---|---|
| `Bad command or filename - "nasm"` | PATH に `C:\NASM` が入っていない（`make dos` 以外で起動した） | `set PATH=C:\NASM;%PATH%` |
| PATH を設定しても見つからない | `C:NASM` と書いている。`C:NASM` は「今いる場所の NASM」という意味になる | `C:\NASM` と `\` を付ける |
| `./nasm` が通らない | `./` は Linux の書き方 | DOS では `nasm` だけでよい |
| `unknown optimization option -OH` | オプションを大文字で打っている。NASM では `-O`（最適化）と `-o`（出力先）、`-F`（デバッグ形式）と `-f`（出力形式）は別物 | オプションは小文字で打つ。`Caps Lock` がオンになっていないか確認する |

DOS のコマンド名とファイル名は大文字・小文字を区別しませんが、**NASM のオプションは区別します**。

## 課題 4：表示する文字を変える

1. `edit hi.asm` で開く
2. 一番下の行を探す
   ```nasm
   msg:    db "Hello, slow world!", 13, 10, "$"
   ```
3. `"` と `"` の間だけを好きな英文に書き換える（`13, 10, "$"` は残す）
4. 保存して閉じる
5. もう一度組み立てて（`nasm -f bin -o hi.com hi.asm`）、実行する（`hi`）

**ポイント**：ソースを書き換えたら、**必ず組み立て直す**こと。`HI.COM` は古いソースから作ったものなので、組み立て直すまで中身は変わりません。

### 実験：`"$"` を消すとどうなるか

`"$"` を消して組み立て、実行すると、自分の文のあとに関係のない文字がたくさん表示されます。

**理由**：文字の表示に使っている DOS の機能（`INT 21h` の `AH=09h`）の決まりは、次の 1 つだけです。

> `DX` が指す場所から 1 文字ずつ表示し、**`$` が出てきたら止まる**

`$` がないと、DOS はプログラムの終わりを越えて、その後ろのメモリーに残っているものまで表示し続けます。
後ろに出てくるのは、直前に NASM が読み込んだソースの断片などです（DOS は使い終わったメモリーを消さないため。推測）。
メモリーのどこかで `$` にぶつかったところで、やっと止まります。

これは **ASCII 文字かどうか**とも、**`org 0x100`** とも関係ありません。

- ソースの `keep this file ASCII only` というコメントは、「DOS の EDIT は UTF-8 を表示できないので、ソースには英数字だけを書くこと」という意味です。
- `org 0x100` は「このプログラムはメモリーの 100h 番地に置かれる」という宣言です。`.COM` は DOS によって必ず 100h 番地に読み込まれる（その前の 0〜FFh には PSP という管理情報がある）ので、NASM はこの値を使って `msg` の番地を計算します。「ここまで」という上限の意味はありません。

**学べること**：アセンブリでは、終わりの印や長さを自分で用意しないと、誰も守ってくれません。
C の文字列の `\0` を忘れたときに起きるバッファオーバーリード（buffer over-read）と同じ種類のバグです。

実験が終わったら、`"$"` を元に戻しておいてください。

## 課題 5（挑戦）：2 行表示する

2 種類の文を、2 行に分けて表示させてください。

**ヒント**：

- 表示を担当しているのは、次の 3 行です。この 3 行をもう 1 組増やします。
  ```nasm
  mov dx, msg
  mov ah, 0x09
  int 0x21
  ```
- 増やしたほうでは、`msg` ではなく、新しく作る `msg2` を指すようにします。
- 一番下に、`msg:` の行を真似して `msg2:` の行を作ります。
- `13, 10` は改行、`"$"` は文字列の終わりの印です。
- 増やす場所は、`mov ax, 0x4C00`（プログラムを終える命令）**より前**です。後ろに置くとどうなるか、考えてみてください。

## 課題 6（挑戦・任意）：`$` を使わずに表示する

### `$` は誰の決まりか

`$` は、アセンブリ言語の決まりではありません。**DOS の `AH=09h` という機能だけの決まり**です。
アセンブリ言語の `db "Hello"` は、ただバイトを並べるだけです。文字列の終わりをどう伝えるかは、呼び出す相手（OS や関数）の約束で決まります。

| 呼び出す相手 | 文字列の終わりの伝え方 |
|---|---|
| DOS の INT 21h **AH=09h** | `$` で終わる |
| C 言語の `puts`、`printf` など | `\0` で終わる |
| DOS の INT 21h **AH=40h** | 長さを `CX` で渡す |
| Linux の `write` システムコール | 長さを `rdx` で渡す |
| Windows の `WriteFile` / `WriteConsole` | 長さを引数で渡す |

### 課題

`hi.asm` を AH=40h を使う形に書き換えて、`"Price: $5"` が最後まで表示されることを確かめてください。AH=09h では、`$` のところで表示が止まってしまう文です。

```nasm
        mov ah, 0x40            ; INT 21h AH=40h: write to handle
        mov bx, 1               ; handle 1 = stdout (screen)
        mov cx, msglen          ; number of bytes
        mov dx, msg             ; DS:DX -> string
        int 0x21
        ...
msg:    db "Price: $5", 13, 10
msglen  equ $ - msg             ; length, computed by NASM
```

**紛らわしい点**：`msglen equ $ - msg` の `$` は、文字列の終わりの印ではありません。
NASM の記号で、「今この行の番地」という意味です。`$ - msg` は「今の番地 − 文字列の先頭の番地 = 文字列の長さ」になります。

- 引用符の中の `"$"` → ただの文字（AH=09h の終わりの印）
- 引用符の外の `$` → NASM が計算する番地

### 参考：Linux（x86-64）で同じことをすると

```nasm
        mov rax, 1              ; syscall 1 = write
        mov rdi, 1              ; fd 1 = stdout
        mov rsi, msg            ; address of the string
        mov rdx, msglen         ; length
        syscall
```

「どこに・何を・何バイト」を渡すという形は、DOS の AH=40h と同じです。違うのはレジスタの名前と、呼び出し方（`int 0x21` か `syscall` か）だけです。

長さを渡す方式のほうが安全です。終わりの印を忘れても、メモリーの先まで読み進めることがありません。また、文字列の中に `$` や `\0` そのものを含められます。
