### MS-DOS 4.00 にした理由

ユーザーは「8086 の時代の MS-DOS の動きに寄せたい」と考えていました。FreeDOS の EDLIN（`make dos`）では、行を書き直すときに F3 で元の行を呼び出せず、ユーザーが困っていたためです。そこで、Microsoft が MIT ライセンスで公開した MS-DOS 4.00 のソースを、同梱のツール（MASM、NMAKE、LINK など）で DOSBox-X の中でビルドしています。

### ビルドで直した、取得したソースの問題（`scripts/get-tools.sh msdos4`）

- U+FFFD（文字化けの置き換え文字）を `=` に置き換える
- 改行が LF だけになっているので、**テキストファイルだけ** CRLF に直す（バイナリまで変えると MASM.EXE などが壊れた）
- `*.SKL` の最後の Ctrl-Z の行を消す
- 読み取り専用のファイルがあるので、取り直す前に `chmod -R u+w` してから消す

### 起動フロッピーで分かったこと（`scripts/msdos4-img.sh`）

- IO.SYS と MSDOS.SYS は、ルートディレクトリの先頭 2 つに、この順で置く必要がある。`mkfs.fat -n`（ボリュームラベル）を付けると先頭を取られて、「Non-System disk」になる
- ブートセクタは、先頭 62 バイト（BPB）を mkfs.fat のまま残し、残りのコードを MSBOOT.BIN（ファイル内の 0x7C00 以降）で置き換える

ユーザーが自分で調べたり質問したりした話題（説明済み）：

- `org 0x100` の理由（PSP、CP/M のゼロページの名残）
- ニーモニックの名前（`mov` = move、`int` = interrupt、`db` = define byte など）
- `msglen equ $ - msg` の仕組み（NASM が組み立てるときに番地を数える。`$` は今の行の番地。実行時には計算しない）
- `13, 10`（CR と LF）の意味。`"..."` の中では `\r\n` が使えず、バッククォート `` `...` `` なら使えること
- `AH=40h` には終わりの文字がない（`CX` の長さだけ書く）
- EDLIN の使い方：`i` は**行番号を先に**書く（`12i`）。`i11` と打つと先頭に入る。`e` = 保存して終了、`q` = 保存せずに終了、`12,14d` = 削除（後ろの行から消すと番号がずれない）
- MS-DOS 4.00 には Tab 補完も `MOVE` もない（`MOVE` は 6.0 から。コピーして `del` する）。`cd` は名前を最後まで打つ
- NASM が遅い理由（現代の 1.7MB の 32 ビット版を、0.3 MIPS ほどの CPU で動かしているため）。当時は MASM 5.1 や TASM だった

## 4. 分かっている問題・確かめていないこと

- **C: に書いたものは消える。** DOSBox-X が mount したフォルダーを FAT に変換してゲストに見せているためで、書き戻しはない（試験で確認）。課題の md と README には書いた。
- **B: の中のフォルダー（例：`B:\LESSON`）は書き戻されない。** ユーザーは一度 `B:\LESSON` で作業したので、閉じる前に `B:\` にコピーするよう伝えた。
- `make run` は、起動のたびに `work/HELLO.COM` を上書きする。
- jpkey：「半角/全角」キーは何もしていない（US の `` ` `` が出る）。DOSBox-X での「ろ」と「¥」のキーは、ユーザーの操作から問題なさそうだが、全部のキーを確かめたわけではない。
- `make msdos4-run` を DOSBox-X のウィンドウで通しで動かしたのはユーザーだけで、エージェントは `-silent` と QEMU でしか試していない。
- コマンドの記録は `make dos`（4DOS）だけ。MS-DOS 4.00 で打ったものは記録されないので、ユーザーのスクリーンショットが頼り。
